# Data policy

The repository contains synthetic recordings for deterministic lessons and tests. A
synthetic recording is generated by code, represents no person, and must be labeled as
synthetic in its metadata and documentation.

## Do not commit participant raw data

Do not add human participant raw EEG to this repository, even when names have been
removed or Git LFS is used. Do not commit:

- raw or lightly processed participant EEG;
- filenames, headers, markers, notes, or metadata that identify or could re-identify a
  participant;
- consent forms, recruitment records, clinical information, or study keys; or
- private device captures, calibration sessions, or classroom recordings.

Keep local recordings under an ignored directory such as `data/private/`, `data/raw/`,
`participant-data/`, or `captures/`. The ignore rules reduce mistakes; they do not
replace consent, ethics review, access control, retention rules, or secure deletion.

## Acceptable repository data

The following may be proposed for review:

- deterministic synthetic data generated by a committed script and fixed seed;
- small fixtures that contain no measurements from a person; and
- aggregate, non-reconstructable numerical reference results derived under an
  approved protocol.

If a lesson needs a public human dataset, keep it outside this repository and provide a
download script or source link only after verifying its license and redistribution
terms. Record its source, version, checksum, citation, and expected format. Users remain
responsible for accepting the source dataset's terms.

Every teaching dataset should document whether it is synthetic or externally sourced,
its sample rate, amplitude unit, channel order, marker and condition definitions,
generation or acquisition method, license, and checksum where practical.

## Accidental disclosure

If sensitive data is committed, stop sharing the affected revision and follow
`SECURITY.md` immediately. Deleting the working-tree file is insufficient because Git
history may still contain it.
